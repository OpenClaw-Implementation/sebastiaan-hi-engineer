Hi-Engineer: the data engine behind the EPCM Guide

This guide explains, from the top down, why Hi-Engineer exists, what is inside the web application, what data it holds today, what is live in production, how the pipeline works, how often it runs and what it costs. It assumes no prior knowledge of the project.

Data as of 9 October 2026 Pilot market: the Netherlands Heroku app: hi-engineer-app
0In one minute

The short version

The EPCM Guide (epcmguide.com) will be a public directory of suppliers to engineering, procurement and construction projects. Hi-Engineer is the back-office tool that finds those suppliers, fills in their details, tags them, collects their job openings and news, and exports the result so a portal can show it.

What works today

  • Scraping exhibitor lists from 23 of 26 trade-show pages.
  • A four-provider enrichment chain that fills website, LinkedIn, industry and summary.
  • Automatic discovery of each supplier's jobs and news pages, and extraction of their listings.
  • The master Excel (1,975 companies, contacts, taxonomy) is loaded into the database.

What needs attention

  • The redesigned interface is built and tested but not yet deployed.
  • No pipeline has run since 16 July — the daily schedule is not active.
  • Only 14 of 791 contacts have an email address.
  • The media-portal scraper produces nothing yet (all 9 portals block or need JavaScript).

2The big picture

From a trade-show page to a portal listing

Every record moves through the same six stages. Each stage is a separate piece of code, so a failure in one does not break the others.

Stage 1

Collect

Scrape exhibitor lists from trade shows; import the master Excel.

Stage 2

Normalise

One row per company in a single companies table.

Stage 3

Enrich

Paid data providers fill website, LinkedIn, industry, summary.

Stage 4

Discover content

Find each supplier's jobs and news pages, extract the listings.

Stage 5

Classify

Tag companies by category, jobs by role, news by topic.

Stage 6

Export

CSV and an Airtable schema, ready for Airtable or Softr.

Inputs

26 trade-show exhibitor pages, 9 industrial media portals, and the master Excel workbook.

The core

A Flask web application on Heroku with a Postgres database. Everyone works in the same browser interface.

Outputs

A clean, tagged supplier directory with contacts, jobs and news — downloadable or pushed to Airtable.

What Hi-Engineer is not. It is not the public website, it does not send emails to anyone, and it does not copy full article text. It collects and organises data; the portal shows it.

How to deploy the redesign

From the repository folder, after reviewing the changes:

git add -A && git commit -m "EPCM pilot revamp" && git push heroku main

The database needs nothing further: tables are created automatically when the app starts, and that step is safe to repeat. To undo a bad deploy: heroku releases:rollback -a hi-engineer-app.

6How it works

The pipeline, stage by stage

Each stage below says what goes in, what happens, what comes out, and the file that does it.

Stage 1 · Collect

Trade-show exhibitor lists

Each of the 26 source URLs is stored with a parser that knows its page layout:

  • FoodTech-style (3): one plain request returns every exhibitor card.
  • Easyfairs-style (11): plain request; only the first ~20 exhibitors per show are public, so names are read from the link addresses.
  • Firecrawl (9): the list is drawn by JavaScript, so Firecrawl renders it in a browser first, then one of five extractors reads it.
  • Unsupported (3): kept on the list so the reason is visible.

Files: scrapers/event_sources.py, scrapers/exhibitors.py, scrapers/firecrawl.py

Master Excel import

A one-off command reads every sheet of the workbook and writes it to the database:

  • Companies are matched by name; new ones are added, existing ones get blanks filled.
  • Jobs and news page addresses already found by the scrapers are never overwritten.
  • Contacts are matched by personal LinkedIn address, so re-running does not duplicate them.

File: import_excel.py · run: python import_excel.py "<path>.xlsx" (add --dry-run to preview)

Media portals

Nine industrial and food portals are fetched with plain requests. None currently yields a company list: five need JavaScript, one blocks the server with HTTP 403, and three return pages where the parser finds nothing. File: scrapers/media.py

Stage 2 · Normalise

Every exhibitor becomes one row in the companies table, keyed by company name. If the same company appears at two shows, the row is updated rather than duplicated, and fields that a later step filled in are kept. File: normalize.py

Stage 3 · Enrich

Each company is passed through a chain of data providers, cheapest first. As soon as the key fields are filled, the chain stops, which keeps cost down.

1 · on

IcyPeas

People search returns company website, LinkedIn, industry.

2 · off

FullEnrich

Switched off: account out of credit.

3 · off

AI Ark

Switched off: account out of credit.

4 · on

Apollo

Organisation lookup by domain; fills what IcyPeas missed.

5 · free

Site probe

Tries /nieuws, /news, /vacatures, /careers… on the website.

A company ends as enriched when at least one provider filled data, or terminal when all were tried and nothing was found. Every attempt is recorded with its duration and cost, and shown live on the Logs tab. Files: enrichers/cascade.py and one file per provider in enrichers/

Stage 4 · Discover content

Jobs pipeline

For each company with a website: use the known jobs page or probe common paths, fetch it, collect links that look like vacancies, and save them.

File: scrapers/jobs_pipeline.py

Articles pipeline

The same steps for the news or blog page. Each item keeps a "first seen" and "last seen" date, so re-runs add new items and refresh old ones without duplicates.

File: scrapers/articles_pipeline.py

Both share one link extractor that strips page headers, footers and menus before reading links (scrapers/listing_extractor.py). It still lets some buttons through, which is why "navigation noise" appears in the data.

Stage 5 · Classify

Company → category

The free-text category from the Excel or the trade show is matched against keyword rules and mapped to one of 11 top-level categories.

taxonomy.py

Job / contact → role

The title is matched against 27 role rules, engineering roles first (MEP, Civil, Structural, Process, Automation, E&I, BIM), then PM, construction manager, architect, HSE, procurement and others.

scrapers/role_classifier.py

News → topic

The title is matched against 15 topic rules (launch, partnership, trade show, award, sustainability…). "Read more" buttons and dates are tagged as noise.

scrapers/topic_classifier.py

Recommended cadence

A cadence that keeps the data fresh at low cost, once the schedule is switched on:

Daily

Jobs and articles

Both pipelines. Plain HTTP only, so no provider cost — only a few minutes of dyno time.

Weekly

Trade-show scrape

All 26 sources. Exhibitor lists change slowly; weekly uses about 36 Firecrawl credits a month.

On demand

Enrichment & import

Enrich new companies in batches you choose; re-import the Excel whenever it changes.

To check or set the schedule: heroku addons:open scheduler -a hi-engineer-app. The Scheduler add-on itself is free; jobs use dyno time while they run.

11Glossary

Terms used in this guide

TermMeaning
EPCMEngineering, Procurement, Construction Management — the project model the guide's suppliers serve
SupplierA company that sells products or services into EPCM projects; one row in companies
SourceA URL the scrapers read from, such as a trade-show exhibitor list
ParserThe piece of code that knows how to read one kind of source page

Topic tagThe kind of news item, e.g. trade show, partnership, sustainability
